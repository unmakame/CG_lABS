# Лабораторная 3: текстуры, UV и анимированная выборка

Сфера, матрицы и освещение сохраняются: [первая работа](Лаба_1_Математика.md), [вторая работа](Лаба_2_Математика.md). Ниже разобраны вычисления текстурирования и размещения данных.

## 1. UV-параметризация сферы

Код: [makeUvSphere](../lab3/src/sphere_mesh.hpp).

Для индексов сетки i,j и разбиений M=12,N=8:

```text
u=i/M=φ/(2π)
v_tex=1−j/N=1−θ/π
```

Обе координаты лежат в [0,1]. U обходит сферу вокруг вертикали, V идёт от нижнего полюса к верхнему. Переворот V согласуется с вертикальным переворотом картинки при загрузке stbi_set_flip_vertically_on_load(1).

На шве совпадающие пространственные вершины имеют U=0 и U=1. Если оставить одну вершину, интерполяция через шов могла бы пробежать через середину картинки. У полюсов несколько U соответствуют одной позиции; идеальной прямоугольной развёртки сферы без искажений не существует.

## 2. Выборка изображения

Код: [loadTexture](../lab3/src/scene_renderer.hpp), [scene.frag](../lab3/shaders/scene.frag).

Изображение — сетка W×H текселей. UV — нормализованный адрес. Центр текселя (i,j) расположен примерно в ((i+0.5)/W,(j+0.5)/H). В режиме REPEAT выход за [0,1] повторяет картинку; координата фактически берётся по модулю 1.

Сэмплер использует линейную фильтрацию. Внутри четырёх соседних текселей с локальными долями a,b:

```text
C=(1−a)(1−b)C00+a(1−b)C10+(1−a)bC01+abC11
```

Это билинейная интерполяция. Вершинные UV интерполируются по треугольнику с перспективной коррекцией. Для экранных барицентрических весов λi и clip-w вершин:

```text
UV = Σ(λi·UVi/wi) / Σ(λi/wi)
```

Без деления на w текстура в перспективе растягивалась бы неправильно. GPU выполняет это автоматически для обычных smooth-входов шейдера. В текущем коде один mip-уровень, анизотропная фильтрация выключена.

## 3. Альбедо, specular и emissive

Код: scene.frag и createDescriptors.

```text
A = texture(albedoMap,UV).rgb ⊙ albedoTint
S = texture(specularMap,UV).rgb ⊙ specularTint
E = texture(emissiveMap,UV).rgb
C = ambient⊙A + Σ BlinnPhong(N,V,L,J,A,S,q) + E
```

A задаёт основной цвет поверхности, S — где и каким цветом виден блик, E прибавляется после освещения. При выключенных источниках и нулевом ambient остаётся E, что создаёт видимость свечения. Эта карта не освещает соседние объекты; bloom и глобальное освещение здесь не реализованы.

У Earthlike подключены все три карты. У Marble specular и emissive заменены чёрной текстурой 1×1. Чёрный равен (0,0,0): умножение обнуляет блик, а прибавление нуля не создаёт свечения. Цветовой Tint может дополнительно менять альбедо. Параметр q управляет шириной блика, карта S — его амплитудой.

Цвета хранятся в формате UNORM: байт k отображается в k/255. Автоматического декодирования sRGB для этих карт нет; это ограничение цветового расчёта текущей учебной реализации. Отдельного тонального отображения тоже нет, поэтому значения выше диапазона вывода могут насыщаться.

## 4. Нетривиальное сэмплирование во времени

Код: ветка options.animatedSampling в scene.frag.

Сначала берётся C0=texture(albedoMap,UV). Для второй выборки координаты центрируются: p=UV−(0.5,0.5). Угол меняется как α=0.18sin(0.7t).

В GLSL аргументы mat2 задают столбцы. Конструкция mat2(cosα,−sinα,sinα,cosα) в текущем коде поэтому даёт:

```text
u'=cosα·px+sinα·py+0.5+0.035t
v'=−sinα·px+cosα·py+0.5
```

Это поворот на −α в обычной математической плоскости, затем перенос по U. Амплитуда угла — 0.18 рад ≈10.3°, период углового колебания 2π/0.7≈8.98 секунды. Перенос проходит одну ширину текстуры примерно за 28.57 секунды при непрерывном времени t.

После второй выборки C1=texture(albedoMap,(u',v')) применяется:

```text
k=0.25+0.15sin(t)                 — диапазон [0.10,0.40]
C_mix=(1−k)C0+kC1
m=0.85+0.15sin(t+12v)            — диапазон [0.70,1.00]
C_albedo.rgb=C_mix.rgb·m
```

Так одновременно выполняются выборки по разным UV, их смешивание и пространственно-временная модуляция цвета. Это формулы эффекта, а не преобразование самой геометрии.

Флаг и t передаются через MaterialPush/vkCmdPushConstants. Параметры модели остаются в UBO. Флаг animatedSampling задаётся отдельно для каждой модели; маркеры его не получают.

## 5. Два независимых времени

Код: Update в scene_renderer.hpp, вычисление dt в main.cpp.

Движение использует собственную накопленную фазу ModelState::phase с множителем animationSpeed_. Эффекты текстуры используют textureTime_, которое увеличивается только при textureAnimationPlaying_. Поэтому пауза перемещения и пауза текстуры — разные переключатели.

Оба приращения используют положительное конечное dt без обрезания. На паузе соответствующая фаза не увеличивается. При сворачивании окна отсчёт кадра сбрасывается. Фазы хранятся в double; перед отправкой времени текстурного эффекта в GLSL выполняется преобразование в float.

## 6. Шум Перлина для emissive

Код: [assets/generate_textures.py](../lab3/assets/generate_textures.py), функции perlin и fade.

Для точки (x,y) определяется целая ячейка (floor(x),floor(y)) и дробное положение (xf,yf). В четырёх углах выбираются псевдослучайные градиенты g. В каждом углу вычисляется скалярное произведение g на вектор от угла к точке. Получаются a,b,c,d.

Веса интерполяции вычисляются через fade(s)=6s⁵−15s⁴+10s³. У этой функции первая и вторая производные равны нулю в 0 и 1: соседние ячейки соединяются плавно.

```text
u=fade(xf), v=fade(yf)
noise=(a+(b−a)u)(1−v)+(c+(d−c)u)v
```

Для карты свечения складываются пять октав: частота каждой следующей удваивается, амплитуда делится на два. Сумма делится на сумму амплитуд:

```text
n = Σ[2^(−k) · perlin(u·8·2^k,v·8·2^k)] / Σ2^(−k), k=0..4
glow = clamp((n+0.12)·2.8,0,1)^1.7
E_bytes = (255·glow,104·glow,17·glow)
```

Степень 1.7 подавляет слабые участки, оставляя яркие пятна. Разные коэффициенты каналов задают оранжевое свечение. Генератор использует фиксированный seed=5, поэтому карты воспроизводимы. Картинка создаётся заранее в файл и затем загружается приложением.

Там же Earthlike строится порогом суммы трёх частот шума: continent>0.035 считается сушей, остальное водой; полярные полосы окрашиваются отдельно. Specular ярче на воде (205), чем на суше (32). Marble использует sin(21u+5sin(11v)+3perlin(8u,8v)), создающий искривлённые полосы.

## 7. Выравнивание динамического UBO

Код: Init, createDescriptors и Draw в scene_renderer.hpp.

Пусть S=sizeof(ModelUniforms), A=minUniformBufferOffsetAlignment. Начало каждой структуры должно быть кратно A:

```text
stride=ceil(S/A)·A
offset(i)=i·stride
```

При A — степени двойки эквивалентная битовая формула: stride=(S+A−1)&~(A−1), она используется в коде. Здесь две mat4 и две vec4 дают S=160 байт при текущих типах. Например, при A=256 stride=256, смещения моделей: 0,256,512… Реальное A запрашивается у GPU.

Все модели хранятся в одном буфере. Набор дескрипторов выбирается по материалу, а dynamic offset — по текущей модели. Дескриптор указывает диапазон одной структуры, смещение выбирает её запись. Это адресная арифметика Vulkan, формулу света она не меняет.

## 8. Staging и объём данных

Для RGBA8 изображения W×H требуется W·H·4 байт. Для вершин — count·sizeof(Vertex), для uint32 индексов — count·4. Не следует вручную предполагать размер C++ структуры: компилятор может добавлять выравнивание, поэтому используется sizeof.

CPU заполняет доступный ему staging-буфер, затем GPU копирует данные в DEVICE_LOCAL ресурс. Барьеры задают порядок доступа: завершить запись переноса перед чтением шейдером или вершинным блоком. На Apple Silicon память физически общая; DEVICE_LOCAL — свойство Vulkan memory type, а не обещание отдельного физического чипа VRAM.

## Что объяснить на защите

Почему UV имеют шов; как работает линейная фильтрация; зачем перспективная коррекция; что меняет specular, а что emissive; почему чёрная заглушка убирает эффект; какие именно две выборки выполняет шейдер; что передаётся через push constants; как выровнен dynamic UBO; как из градиентного шума получается карта свечения.
