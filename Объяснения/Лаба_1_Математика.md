# Лабораторная 1: сфера, проекции и движение

Этот разбор соответствует текущему коду варианта 5. Обозначения: векторы представлены столбцами, углы внутри sin/cos заданы в радианах. Перевод градусов в радианы: α_rad = α_deg · π / 180.

## 1. Координаты сферы

Код: [makeUvSphere](../lab1/src/sphere_mesh.hpp).

Сфера радиуса r с центром в начале координат удовлетворяет x² + y² + z² = r². Для построения сетки используются два угла:

```text
θ = π · j / N         — угол от верхнего полюса, 0 ≤ j ≤ N
φ = 2π · i / M        — угол вокруг вертикальной оси, 0 ≤ i ≤ M
x = r sin(θ) cos(φ)
y = r cos(θ)
z = r sin(θ) sin(φ)
```

В коде r = 1, M = 12, N = 8. Поэтому верхний полюс — (0,1,0), нижний — (0,-1,0), а при θ = π/2 и φ = 0 получается (1,0,0).

Почему это сфера: x² + z² = r²sin²θ(cos²φ + sin²φ) = r²sin²θ. Добавление y² даёт r²(sin²θ + cos²θ) = r².

Хранятся (M+1)(N+1) = 13·9 = 117 вершин. Вершины шва имеют одинаковые позиции при φ = 0 и φ = 2π, но разные текстурные координаты. Полюса тоже продублированы для UV. Поэтому 117 — количество записей вершин, а не уникальных пространственных точек.

Каждая обычная ячейка сетки разбивается на два треугольника. У полюсов один из них имел бы нулевую площадь, поэтому он пропускается. Всего 2M(N−1) = 168 треугольников и 504 индекса. Индексы хранят номера вершин; обход треугольников направлен наружу.

## 2. Векторы и нормали

Вектор p = (x,y,z) задаёт положение относительно центра. Длина |p| = √(x²+y²+z²). Нормализация: normalize(p) = p/|p|.

Для единичной сферы |p| = 1, поэтому наружная нормаль n = p. В первой работе освещение не применяется, но нормали подготавливаются для следующих работ.

## 3. Процедурный цвет

Код: makeUvSphere и [фрагментный шейдер](../lab1/shaders/scene.frag).

Каждый канал цвета зависит от соответствующей координаты:

```text
R = 0.35 + 0.65 · (0.5 + 0.5x)
G = 0.35 + 0.65 · (0.5 + 0.5y)
B = 0.35 + 0.65 · (0.5 + 0.5z)
```

Координаты лежат в [-1,1]. Выражение 0.5+0.5x переводит этот диапазон в [0,1], а итоговый цвет лежит в [0.35,1].

Цвет из ColorEdit умножается покомпонентно на интерполированный цвет вершин: C = C_user ⊙ C_vertex. Например, красный пользовательский цвет (1,0,0) обнуляет зелёный и синий каналы. Внутри треугольника GPU интерполирует атрибуты; в перспективе используется коррекция интерполяции по w.

## 4. Однородные координаты и матрица модели

Код: [modelMatrix](../lab1/src/scene_renderer.hpp), [scene.vert](../lab1/shaders/scene.vert).

Точка представляется как (x,y,z,1). Четвёртая координата позволяет выразить перенос матрицей 4×4. Направление обычно представляют с w=0, чтобы перенос на него не действовал.

```text
T = [1 0 0 tx]       S = [sx 0  0  0]
    [0 1 0 ty]           [0 sy  0  0]
    [0 0 1 tz]           [0  0 sz  0]
    [0 0 0  1]           [0  0  0  1]
```

Повороты в правой системе координат:

```text
Rx = [1  0   0]   Ry = [ cosα 0 sinα]   Rz = [cosα -sinα 0]
     [0 cosα -sinα]     [ 0    1 0   ]        [sinα  cosα 0]
     [0 sinα  cosα]     [-sinα 0 cosα]        [0     0    1]
```

Здесь показаны блоки 3×3; в матрице 4×4 последняя диагональ равна 1. В коде M = T·Rx·Ry·Rz·S. Для столбцов операции применяются справа налево: сначала масштаб, затем Rz, Ry, Rx и перенос. Перестановка матриц меняет результат. Масштаб ограничивается снизу 0.01, чтобы матрица оставалась обратимой.

## 5. Камера и проекция

Код: cameraForward, viewProjection в scene_renderer.hpp. Подробный вывод матрицы камеры дан в [разборе второй работы](Лаба_2_Математика.md).

Полная цепочка: p_clip = P·V·M·p_local. M переводит модель в мир, V — мир в координаты камеры, P — в координаты отсечения. GPU делит xyz на w и переводит результат в экранные координаты.

Для перспективы f = 1/tan(FOV/2), aspect = ширина_сцены/высота. В координатах камеры видимые точки имеют z < 0:

```text
x_clip = (f/aspect) · x_camera
y_clip = f · y_camera            — до инверсии Y в Vulkan
w_clip = -z_camera
x_ndc = x_clip / w_clip
```

Чем дальше точка, тем больше |z| и меньше её изображение. Для правой камеры и глубины [0,1]: z_clip = far/(near−far)·z + far·near/(near−far). После деления near переходит в 0, far — в 1. В коде near=0.05, far=100.

Ортографическая проекция не уменьшает размер с расстоянием:

```text
x_ndc = 2x/(right−left) − (right+left)/(right−left)
y_ndc = 2y/(top−bottom) − (top+bottom)/(top−bottom)
z_ndc = (−z−near)/(far−near)
```

В коде границы X равны ±2.6·aspect, Y — ±2.6. Матрица P имеет инверсию Y: proj[1][1] *= -1 для выбранного направления экранной оси Vulkan. aspect использует 72% ширины окна: остальное занимает панель.

Буфер глубины хранит z_ndc ближайшего записанного фрагмента. Очистка в 1 и сравнение LESS позволяют ближним поверхностям закрывать дальние независимо от порядка рисования.

## 6. Траектория, скорость, dt и пауза

Код: цикл в [main.cpp](../lab1/src/main.cpp), Update и modelMatrix в scene_renderer.hpp.

```text
dt = currentTime − previousTime
step = dt, если dt конечное и положительное; иначе 0
phase_new = phase_old + step · speed     — только при Play animation
```

Поле ModelState::phase является накопленной фазой. speed задаёт радианы фазы в секунду; при speed=1 полный оборот занимает около 2π секунд при обычной работе приложения. При 60 FPS dt≈1/60, при 30 FPS dt≈1/30: за секунду суммарная фаза одинакова.

Каждая модель хранит собственную фазу `phase` типа double. `advancePhase` из `src/scene_math.hpp` увеличивает её только при включённых общей и индивидуальной анимациях. dt не обрезается: при 10 FPS также сохраняется скорость. При свёрнутом окне main сбрасывает предыдущую отметку времени, исключая скачок после восстановления.

Для модели с номером i задаются b = i·2.094 и a = phase+b:

```text
x = x0 + R(cos a − cos b)
z = z0 + R(sin a − sin b)
y = y0 + 0.3R(sin 2a − sin 2b)
rotationY = заданный_угол + phase
```

Вычитание начальных значений даёт нулевое смещение при phase=0. Горизонтальная часть круговая, вертикальная совершает два колебания за оборот. Разная начальная фаза разводит движение объектов.

На паузе накопленная фаза не меняется, поэтому положение и поворот сохраняются. Скорость входит в приращение фазы: её изменение не пересчитывает уже пройденный путь и не вызывает скачок. Изменение самого радиуса может мгновенно изменить положение — это редактирование траектории. Отключение Animate this sphere замораживает её фазу, а Reset animation явно обнуляет фазы всех моделей.

## 7. Дополнительная сетка поверхности

В scene.frag UV умножаются на (12,8). fract выделяет положение внутри ячейки, расстояние до ближайшей границы определяет линию. fwidth оценивает изменение координаты на пиксель, чтобы толщина линии меньше зависела от масштаба. Сетка меняет цвет поверхности, геометрию она не меняет.

## Что объяснить на защите

Почему x²+y²+z²=1; почему 117 записей при примерно 100 вершинах; почему порядок матриц важен; чем перспектива отличается от ортографии; почему dt нужен для независимости от FPS; почему пауза должна останавливать накопление фазы; зачем depth test. VkDescriptorSet связывает данные модели с шейдером, но сам не является математическим преобразованием.
